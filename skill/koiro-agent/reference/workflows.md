## 1. 数据模型

**歌曲**是核心对象，网页地址 `/songs/<UUID>`。一首歌由这几部分组成：

- **基本信息**：标题（必填）、简介、封面（必填，一张图片）。
- **staff**：一组 `{role, name[]}`，例如 `{"role": "作词", "name": ["甲", "乙"]}`。staff 不是独立的对象，只是歌曲里的文字；网站的 staff 页按**名字的精确写法**聚合同一个人参与的歌曲，所以同一个人在不同歌曲里要用同一种写法。
- **音频版本**：一首歌可以有多个音频，例如"主版本""伴奏""人声版"。版本名在这首歌内唯一，**恰好一个是默认版本**（列表和卡片上播放的就是它，下载不指定版本时也下载它）。
- **歌词版本**：一首歌可以有多份歌词，例如"原文""中文翻译""罗马音"。版本名（`key`）在这首歌内唯一，有歌词时**恰好一份是默认歌词**。每份歌词有语种标签（`zh`、`ja`、`en`…），网站的语种页据此聚合歌曲。歌词由按时间排列的行组成，可以给词语加注音。
- **音频与歌词的绑定**：每个音频版本可以绑定这首歌的一份歌词，播放这个版本时就显示这份歌词。绑定只能指向同一首歌的歌词。
- **所属歌单**：一首歌可以在任意多个歌单里。

**歌单**：名称、简介、封面（必填），以及一个有顺序的歌曲列表，网页地址 `/playlists/<UUID>`。删除歌单不会删除里面的歌曲；删除歌曲会把它从所有歌单中移除。

**文件**：封面图片公开可访问；音频私有，播放和下载都需要权限。文件在服务端的 ID（`objectId`）只能通过上传获得，不要自己编造或改写。

## 2. 权限

用户的权限是位掩码，用 `koiro auth status` 查看 `user.permissions`：

| 位  | 名称     | 允许                                                 |
| --- | -------- | ---------------------------------------------------- |
| 1   | VIEW     | 浏览、搜索、读歌词、在线播放                         |
| 2   | DOWNLOAD | 下载音频文件                                         |
| 4   | UPLOAD   | 新建歌曲（含上传封面、音频）                         |
| 8   | ADMIN    | 修改、删除歌曲；新建、修改、删除歌单及调整其中的歌曲 |

例如 `5` = VIEW + UPLOAD，`15` = 全部。权限为 `0` 表示账号已停用。缺少权限的命令以退出码 `4` 失败。

站点可能开放匿名浏览：此时不登录也能执行只读命令（下载除外）；没开放时，未登录的只读命令以退出码 `3` 失败。

开始写操作前，先用 `auth status` 确认有对应权限，没有就直接告诉用户，不要尝试。

## 3. 查找与阅读

**从链接开始。** 用户贴来的链接可以直接作为参数，脚本只看路径、不访问链接本身：

```sh
koiro song view https://<站点>/songs/<UUID> --json
koiro playlist view https://<站点>/playlists/<UUID> --all --json
```

**不知道 ID 时先搜索。** `song search` 同时匹配标题、staff 姓名和歌词正文，按相关度排序。结果里的 `matchType` 是命中部分的数组（`title`、`staff`、`lyrics` 的组合），`matchSnippet` 是命中的片段。搜索结果有多条可能时，把候选列给用户确认，不要自己挑一个。

```sh
koiro song search 风 --json
```

**读完整信息用 `song view`**：返回基本信息、staff、全部音频版本（含 `isDefault`、绑定的 `lyricsId`）、全部歌词版本（每行带 `startMs`，注音写成 `基字(读音)`）、所属歌单。

**按人或语种浏览**：`staff view <名字>`、`language view <代码>` 列出相关歌曲；`staff list`、`language list` 给出概览。

**列表默认只返回一页**（`{items, page, totalPages, total}`）。需要全部时加 `--all`；只需要大概情况时不要加，以免请求过多。

给用户汇报时附上结果里的 `url`，用户可以直接在网页上打开。

## 4. 修改歌曲

需要 ADMIN。修改歌曲的任何部分（标题、简介、封面、staff、歌词、音频版本、所属歌单）都走同一个流程：

1. **导出**当前完整内容：`koiro song export <SONG> > song.json`
2. **只改需要改的地方**，其余字段原样保留。
3. **写回**：`koiro song update <SONG> --file song.json`
4. **核对**：`koiro song view <SONG> --json`，确认改动生效、没有误伤。

`update` 是**整体替换**，务必注意：

- 文档里**没有**的字段会被当成空：缺了 `staff` 会清空 staff，缺了 `lyrics` 会删除全部歌词，缺了 `playlistIds` 会把歌曲移出所有歌单。所以必须以 `export` 的输出为基础修改，不能凭记忆拼一份新文档。
- 音频版本按 `name` 对齐，歌词版本按 `key` 对齐。名字不变的版本会保留（播放器里正在播放的引用不会失效）；改名等于删掉旧的、新建一个；文档里删掉的版本会被删除。
- 所属歌单：仍在 `playlistIds` 里的歌单保持原来的位置；新加入的歌单排到末尾；从 `playlistIds` 里去掉的歌单会移除这首歌。

常见修改：

| 要做的事                   | 在导出的文档里怎么改                                                      |
| -------------------------- | ------------------------------------------------------------------------- |
| 改标题、简介               | 改 `title`、`description`                                                 |
| 增删 staff                 | 改 `staff` 数组；多人写在同一个角色的 `name` 数组里                       |
| 换封面                     | 删掉 `coverObjectId`，写 `coverFile`（本地图片）或 `coverUrl`（网络图片） |
| 修改歌词某几行             | 改对应 `lyrics[].lines`                                                   |
| 用 LRC 整体替换某份歌词    | 删掉这份歌词的 `lines`，写 `lrcFile`                                      |
| 新增一份歌词（如翻译）     | 在 `lyrics` 里加一项，`key` 不能与已有的重复                              |
| 让某个音频版本显示某份歌词 | 把这个版本的 `lyricsKey` 设为那份歌词的 `key`                             |
| 换默认音频版本 / 默认歌词  | 调整各项的 `isDefault`，保证恰好一个为 `true`                             |
| 加一个音频版本             | 在 `versions` 里加一项，写 `name` 和 `audioFile`                          |
| 替换某个版本的音频文件     | 删掉它的 `objectId`，写 `audioFile`                                       |
| 调整所属歌单               | 改 `playlistIds`；歌单 ID 用 `playlist list --all` 查                     |

**删除歌曲**用 `koiro song delete <SONG>`，不可恢复，执行前向用户确认。

## 5. 新建歌曲

需要 UPLOAD。

1. **先查重**：用 `song search <标题>` 看看是否已经有这首歌，有的话告诉用户，由用户决定是修改已有的还是新建。
2. **准备素材**：封面图片（本地文件或网络地址，必需）、至少一个音频文件（必需）、歌词（LRC 文件或手写的行，可选）、staff、要加入的歌单 ID（可选）。
3. **写文档** `song.json`，字段见 [song-document.md](song-document.md)。本地文件用相对于文档的路径。
4. **创建**：`koiro song create --file song.json`。脚本会先上传封面和音频，再提交歌曲，成功后返回 `{id, url}`。
5. **核对**：`koiro song view <id> --json`。

失败时：

- 退出码 `8` 通常是内容校验没通过（如缺封面、版本名重复），按 `message` 修改文档后重试。此前已上传的文件不会被删除，也不影响后续重试，忽略即可。
- 退出码 `7` 时歌曲可能已经创建成功。**先用 `song search <标题>` 确认**，没有再重试，否则会出现两首重复的歌。

## 6. 编写歌词

歌词由行组成，每行：

- `startMs`：开始时间（毫秒，必填，不能为负）；`endMs`：结束时间（可选，不能早于开始）。
- `text`：这一行的文字。
- `rubyByIndex`：注音（可选）。

**有 LRC 时优先用 LRC**，不要手算时间：在文档里写 `lrcFile`，或用 `koiro lyrics from-lrc <文件>` 先转换成行再编辑。LRC 中的 `[ti:]`、`[ar:]` 等元数据行会被忽略，一行有多个时间标签会展开成多行，没有时间标签的行记为 0 毫秒。

**注音**：把 `text` 用 `/` 分成若干段，`rubyByIndex` 以段的序号（从 `"0"` 开始的字符串）为键写读音：

```json
{
  "startMs": 10500,
  "text": "君/の/声/が",
  "rubyByIndex": { "0": "きみ", "2": "こえ" }
}
```

网站显示为 君(きみ)の声(こえ)が。没有注音的行不用分段。因为 `/` 是分段符号，歌词正文里不能出现 `/` 字符本身。

**语种**：`languages` 写这份歌词用到的语言代码，例如日文原文 `["ja"]`、中日双语 `["ja", "zh"]`。常用代码：`zh` 普通话、`yue` 粤语、`nan` 闽南语、`ja` 日语、`en` 英语、`ko` 韩语。

**多份歌词**：原文、翻译、罗马音各作一份，`key` 取直观的名字（如"原文""中文翻译"）。把默认音频版本的 `lyricsKey` 指向最常用的那份。

## 7. 整理歌单

需要 ADMIN。

- **新建**：`playlist create --name <名称> --cover-file <图片>`（封面必需，也可用 `--cover-url`），简介用 `--description` 或 `--description-file`。
- **改名、改简介、换封面**：`playlist edit <PLAYLIST>`，只传要改的选项。
- **加歌**：`playlist add <PLAYLIST> <SONG>...`，按给出的顺序追加到末尾；已经在歌单里的、不存在的、在命令里重复写的歌曲会跳过，返回 `{added, skipped}` 两个计数。
- **移除**：`playlist remove <PLAYLIST> <SONG>`，一次一首，只移出歌单，不删除歌曲。
- **排序**：`playlist reorder <PLAYLIST> <SONG>...` 必须传入歌单里**全部**歌曲的新顺序。先用 `playlist view <PLAYLIST> --all` 取得完整列表，调整顺序后整体传回。缺歌、多歌或重复时脚本会拒绝执行（退出码 `2`），`details` 里的 `missing` / `unknown` 列出差异。
- **删除歌单**：`playlist delete <PLAYLIST>`，不可恢复，执行前向用户确认。

也可以从歌曲一侧调整它属于哪些歌单，见第 4 节的 `playlistIds`。

## 8. 下载音频

需要 DOWNLOAD。

```sh
koiro song download <SONG> --out ./歌名.mp3
koiro song download <SONG> --version 伴奏 --out ./歌名-伴奏.mp3
```

不指定 `--version` 时下载默认版本；指定的版本不存在时，错误的 `details.versions` 会列出可选的版本名。`--out` 已存在时默认拒绝覆盖，确认要覆盖再加 `--force`。下载过程中中断不会留下不完整的文件。

## 9. 登录与错误处理

**登录**：`koiro login` 打印授权地址并尝试打开浏览器。用户在网页上（未登录会先跳到登录页）确认"允许命令行登录"后，命令自动返回。浏览器没打开时，把地址原样转达给用户。授权必须在运行脚本的这台机器上完成。登录有效期 30 天，过期后再次 `login`。

**退出码与处理方式**：

| 码  | 含义                                           | 处理                                   |
| --- | ---------------------------------------------- | -------------------------------------- |
| 0   | 成功                                           |                                        |
| 1   | 本地失败：文件读不到、写不进，配置文件权限不对 | 检查路径；配置文件须为 0600            |
| 2   | 参数错误，或没有配置站点                       | 看错误信息和 `koiro help`              |
| 3   | 未登录或登录过期                               | `koiro login`                          |
| 4   | 当前用户没有这个权限，或账号已停用             | 如实告知用户                           |
| 5   | 资源不存在或不可见                             | 核对 ID / 链接                         |
| 6   | 冲突                                           | 按错误信息处理                         |
| 7   | 网络失败、超时                                 | 申请联网后重试；写操作先核对是否已完成 |
| 8   | 服务端拒绝（如内容校验失败）或响应异常         | 按 `message` 修正后重试                |
| 130 | 已取消                                         |                                        |

错误输出在 stderr：`{"error": {"code": "...", "message": "...", "details": ...}}`。
